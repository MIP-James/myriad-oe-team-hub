# 🛡️ MYRIAD 화이트리스트 가드 (크롬 확장)

아마존 **Report Infringement** 페이지에서 신고하려는 ASIN 의 `Sold by` 셀러가
고객사의 **공식 판매처(화이트리스트)** 인지 자동으로 대조해 오신고를 막습니다.

## 왜 확장 프로그램인가

팀 허브 웹페이지는 브라우저 보안(cross-origin) 때문에 **아마존 페이지의 내용을 읽을 수 없습니다.**
검사는 신고가 실제로 일어나는 그 페이지 위에서 일어나야 하므로 확장이 필요합니다.
반대로 화이트리스트 데이터를 확장 안에 넣으면 셀러 한 명 바뀔 때마다 확장을 재배포해야 하므로,
데이터는 팀 허브에 두고 확장이 내려받아 씁니다.

```
[팀 허브]  관리자 → 화이트리스트 셀러 관리      [이 확장]
  엑셀 업로드 / 직접 편집 → Supabase   ──토큰──▶  6시간마다 목록 캐시
                                                아마존 페이지 Sold by 읽기
                                                → 경고 배너 + 행 강조 + 체크 차단
```

## 설치 (팀원용, 1회)

1. 내려받은 폴더의 압축을 풀어 **고정된 위치**에 둡니다.
   (예: `C:\MYRIAD\whitelist-guard` — 폴더를 지우거나 옮기면 확장이 사라집니다)
2. 크롬 주소창에 `chrome://extensions` 입력
3. 오른쪽 위 **개발자 모드** 켜기
4. **압축해제된 확장 프로그램을 로드합니다** 클릭 → 1번 폴더 선택
5. 팀 허브 → **관리자 → 화이트리스트 셀러 관리** → 맨 아래 **크롬 확장 연결** → **토큰 발급**
6. 표시된 토큰을 복사 → 확장 아이콘 우클릭 → **옵션** → 토큰 붙여넣고 **저장 후 동기화**
7. 툴바 아이콘에 등록 건수가 배지로 뜨면 준비 완료

## 사용법

아마존 신고 페이지에서 ASIN 을 검색하면 **자동으로** 동작합니다.

- `Show offers (n)` 를 확장이 알아서 펼쳐 셀러 목록을 읽습니다
- 결과가 페이지 상단 배너로 표시됩니다
  - ⛔ **빨강** — 화이트리스트와 일치. 신고하면 안 됩니다
  - ⚠️ **노랑** — 이름이 비슷해 확인이 필요합니다
  - ✅ **초록** (우하단) — 일치 없음. 검사는 정상 완료
- 해당 셀러의 표 행이 색으로 강조되고 배지가 붙습니다
- 화이트리스트 셀러의 **체크박스를 켜면 즉시 확인 창**이 뜹니다
- 신고 버튼을 눌러도, 화이트리스트 셀러가 선택돼 있으면 한 번 더 확인합니다

## 지원 국가 도메인 / 언어

`amazon.com` `.ca` `.co.uk` `.de` `.fr` `.it` `.es` `.co.jp` `.com.mx` `.com.au` `.com.br`
`.in` `.nl` `.se` `.pl` `.sg` `.ae` `.sa` `.eg` `.com.tr` `.com.be` — **21개 마켓플레이스**에서 동작합니다.

포털이 현지 언어로 뜨는 경우도 처리합니다.

| 항목 | 처리 방식 |
|---|---|
| 신고 페이지 판별 | `/report/` 경로 + 21개 언어 문구 (`Rechtsverletzung`, `contrefaçon`, `権利侵害` …) |
| `Sold by` 헤더 | 언어별 표현 (`Verkauft von`, `Vendu par`, `販売元`, `판매자` …) |
| `Show offers (n)` 펼치기 | **언어 무관** — 끝에 `(숫자)` 가 붙은 짧은 클릭 요소를 찾습니다 |

`(숫자)` 방식이라 `Show all images (8)` 도 함께 펼쳐지는데, 이미지 목록이 열릴 뿐 무해합니다.
**놓쳐서 검사가 안 되는 것보다 여는 게 낫다**는 판단입니다.
실제로 이동하는 링크(페이지네이션 `(2)` 등)는 누르지 않습니다.

> **혹시 셀러를 못 읽으면** 초록불 대신 **노란 "셀러를 읽지 못했습니다"** 경고가 뜹니다.
> 검사가 안 됐는데 안전하다고 착각하는 상황을 만들지 않기 위한 안전망입니다.
> 이 경고가 뜨면 팝업의 **진단** 내용을 전달해 주세요.

## 확신도 3단계

화이트리스트는 `가게 이름 + 홈페이지 URL` 인데 아마존은 `셀러 표시명` 을 보여주므로
둘이 항상 같지 않습니다. 그래서 확신도를 나눠 표시합니다.

| 단계 | 근거 | 판단 |
|---|---|---|
| **확정** | 아마존 셀러 ID 또는 등록된 아마존 표시명이 일치 | 사실상 확실 |
| **일치** | 가게 이름·별칭·스토어 도메인이 정규화 후 완전 일치 | 거의 확실 |
| **확인** | 부분 포함 / 공통 단어 / 오타 수준 유사 | 사람이 확인 |

**정확도를 올리는 방법:** 신고 화면에서 화이트리스트 셀러를 확인할 때마다,
허브의 해당 셀러 편집 화면에 **아마존 셀러 표시명 / 셀러 ID** 를 적어두세요.
그 셀러는 이후 항상 "확정" 으로 잡힙니다.

## 팝업 기능

툴바 아이콘 클릭 시:

- **상태** — 보관 중인 화이트리스트 건수, 고객사, 마지막 동기화 시각
- **이 페이지 검사** — 읽은 셀러 수 / 일치 건수, `다시 검사`
- **진단** — 확장이 페이지에서 실제로 무엇을 찾았는지 그대로 표시.
  아마존이 페이지 구조를 바꿔 검사가 안 될 때 원인 확인용 (이 내용을 그대로 전달해주세요)
- **셀러 이름 테스트** — 셀러명을 직접 입력해 화이트리스트 대조. 신고 전 수동 확인용

## 문제가 생기면

| 증상 | 확인할 것 |
|---|---|
| 배너가 아예 안 뜸 | 페이지 새로고침 (확장 설치 후 첫 로드 필요) → 팝업의 `진단` |
| "토큰이 유효하지 않습니다" | 허브에서 토큰 재발급 후 옵션에 다시 입력 |
| 셀러를 0명 읽음 | `Show offers` 가 펼쳐졌는지 확인 → 팝업 `다시 검사` → `진단` |
| 등록 건수가 0 | 허브 관리자 페이지에서 화이트리스트가 등록됐는지 확인 |

## 구조

```
manifest.json          MV3 설정
background.js          목록 내려받기 + 6시간 캐시 (요청 수를 낮게 묶어 Cloudflare 한도 보호)
lib/matcher.js         매칭 엔진 (정규화·별칭·도메인·오타 3단계 판정)
content/amazon.js      페이지 읽기 + 경고 렌더 + 체크박스/제출 차단
content/guard.css      주입 UI 스타일 (MYRIAD 브랜드 색)
options/               토큰 설정
popup/                 상태·진단·이름 테스트
```

셀렉터는 **클래스 이름을 쓰지 않고** "Sold by 라는 글자가 있는 헤더 셀" 처럼
사람이 보는 텍스트를 기준으로 찾습니다. 아마존이 내부 클래스를 자주 바꾸기 때문입니다.
